# Evidence dashboard and decision engine

Maintain the single source of truth using the included `../../assets/PROJECT_STATE_TEMPLATE.md` or a user-provided spreadsheet/document; ask for it in later chats if not accessible. Do not pretend the plugin automatically stores sales, analytics, email or history.

For creator partner pipeline, use `crm-command-center` with the bundled offline dashboard or user-authorized data source. Do not imply local-only browser storage is synced into ChatGPT.


## Metrics
Capture dated funnel values and denominators: qualified prospects reached; replies; product demos; price quotes; real commitments; confirmed sales; revenue; refund/chargebacks; cost; time spent; estimated profit and customer objections. Show zeros as zeros and unknown as unknown, never invent observations.

For experiments, compare actual outcomes to pre-registered Pass / Revise / Stop criteria. If sample too small, report **Insufficient evidence** rather than a false win/lose. Use buyer feedback verbatim only with appropriate permission.

## Decisions
- **Proceed** only when key hypotheses pass and prerequisites are met.
- **Revise** if buyers want a different outcome, price or packaging while core problem shows promise.
- **Stop** if economics, buyer access, policy constraints or negative evidence defeat the idea.
- **Gather more evidence** if too few qualified buyers or uncertainty overwhelms rank gap.

When proposing growth, update score, contribution model, capacity, forecast and product roadmap using new evidence. Provide up to three concrete actions with owner, method, deadline, cost and expected observation. Prioritize one factor with the biggest decision impact.
